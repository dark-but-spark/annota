# Duplicate PDF Detection and Merging

Annota can scan the Zotero library for duplicate PDFs and merge their
annotations and notes into a single kept copy.

## What counts as a duplicate

All three conditions must hold:

1. **Same title** — titles are compared after Unicode normalization,
   whitespace collapsing, case folding, and trimming a trailing period.
2. **Identical PDF content** — the files must have the same SHA-256 hash.
   Files with the same text but regenerated bytes are not considered
   duplicates.
3. **No language conflict** — metadata `language` values and a text-based
   script detection pass must agree. Different-language copies are reported
   and skipped, never merged.

The language guard is intentionally conservative. Latin-script languages
cannot be distinguished reliably without a language model, so the detector
reports `latin` for English/French/German/etc. For non-Latin scripts it
distinguishes Chinese, Japanese, Korean, Russian, and Arabic. A Chinese/English
pair will therefore be rejected, while two English copies will merge.

> Translation support is planned for later. Until then, translated PDFs are
> treated as different-language content and are not merged.

## What gets merged

- Unique annotations from duplicate attachments are moved to the kept
  attachment. Annotations that already exist on the kept attachment are
  detected by type, color, text, comment, page index, and rectangle geometry,
  and are left with the duplicate (which goes to the trash).
- Notes attached to duplicate attachments or their parent items are moved to
  the kept item.
- Other child attachments (supplementary files) are re-parented to the kept
  item.
- Tags and collection membership are merged into the kept item.
- Duplicate PDF attachments and their parent items are moved to the Zotero
  trash. PDF files on disk are not deleted.

The kept attachment is the one with the most existing annotations, with the
oldest item and lowest attachment ID as tie-breakers. This minimizes the number
of annotations that need to be moved.

## MCP tools

`find_duplicate_pdfs` is read-only and returns groups with a `mergeable` flag,
the chosen target, duplicate members, languages, and annotation counts.

`merge_duplicate_pdfs(dry_run=True, title=None)` previews by default. Call it
with `dry_run=false` to apply. Applying a merge requires Zotero to be closed
because Zotero holds an exclusive SQLite lock while running.

Example flow:

```text
find_duplicate_pdfs()
merge_duplicate_pdfs(dry_run=true, title="microarchitecture")
merge_duplicate_pdfs(dry_run=false, title="microarchitecture")
```

## Command line

```bash
# Preview all duplicate groups
python merge_duplicate_pdfs.py

# Preview groups whose title contains a phrase
python merge_duplicate_pdfs.py --title "microarchitecture"

# Apply (close Zotero first)
python merge_duplicate_pdfs.py --apply

# Machine-readable output
python merge_duplicate_pdfs.py --json
```

## Safety notes

- Only byte-identical files under the same title are merged.
- Different metadata or detected languages cause the group to be skipped.
- Applying a merge is transactional: an error rolls back the whole group.
- Duplicates are moved to the trash, so the operation can be undone from
  Zotero.
- The storage files of trashed items are left in place until Zotero empties
  the trash.
- Zotero sync may need to upload the moved annotations/notes and the trash
  entries after restarting; keep Zotero open afterward until sync completes.
